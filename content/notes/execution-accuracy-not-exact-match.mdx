title: "For text-to-SQL, measure execution accuracy"
date: "2026-06-18"

---

Two SQL queries can be spelled completely differently and return exactly the same rows. So string-matching generated SQL against a reference — *exact-match accuracy* — punishes correct answers for cosmetic reasons.

The metric that matters is **execution accuracy**: run both queries against the database and compare result sets. That is why the benchmark run uses [Spider](https://yale-lily.github.io/spider), whose harness scores execution rather than text.

The scoped Spider dev run has since completed, on 10 July 2026: DBWhisper's generation model alone — each database's schema in context, no retrieval or policy layer — matched the gold result set on 101/139 scored questions.

**Correction, 16 November 2026:** an earlier version of this note also quoted an end-to-end golden-query result and called its exact match a harsh reading. DBWhisper's own claim audit has since withdrawn that result: it cannot be reproduced from a clean checkout, it ran on a prompt that has been retired, and it compared result sets as a plain set — which collapses duplicate rows and is looser, not harsher, than a multiset comparison. It is no longer published here.

"The model felt right" is not a number. The Spider figure, its method, and the nine questions a provider rate-limit forced out of the sample are on [Evals](/evals), along with the retired run and the reason it was retired.
